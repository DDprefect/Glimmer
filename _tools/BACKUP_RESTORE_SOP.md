# 微光摄影社 · 备份与恢复操作手册（SOP）

> 适用对象：社长 / 技术负责人。建议每学期交接时走一遍「演练清单」。
> 相关实现：`api/_lib/backup.js`（导出逻辑）、`api/_lib/csv.js`（字段定义）、`vercel.json`（每月 1 日自动执行）。

## 1. 备份到底备了什么（先看清边界）

| 内容 | 是否备份 | 说明 |
| --- | --- | --- |
| 报名记录（submissions） | ✅ CSV | 每月一份 `submissions-YYYY-MM.csv` |
| 作品数据（photos） | ✅ CSV | 每月一份 `photos-YYYY-MM.csv`（含标题、署名、分类、状态、EXIF） |
| 图片文件本体 | ❌ **不在备份内** | 图片只存在于 COS 桶；`_original/` 私有原图也在同一个桶 |
| 桶策略、环境变量、代码 | ❌ | 代码在 GitHub；环境变量/桶策略需另行记录（切勿写入本仓库） |

**⚠️ 最重要的风险认知**：如果 COS 桶被误删、欠费回收或账号异常，**所有图片会永久丢失**（CSV 里只有文字信息，没有图片二进制）。对策见第 5 节。

## 2. 备份存在哪、怎么取

- 自动：每月 1 日 00:00（北京时间）由 Cron 执行，写入 COS `_backup/<YYYY-MM>/`。
- 手动：管理后台 → 报名列表页 → **「立即备份全部数据」** → 返回当月的两份 CSV 与**签名下载链接（有效期 7 天）**。
- 匿名访问 `_backup/*` 会被拒绝（桶策略已配置），必须走签名链接或 COS 控制台下载。

## 3. 恢复场景 A：数据误删（表结构正常）

1. 下载对应月份的 `submissions-YYYY-MM.csv` / `photos-YYYY-MM.csv`；
2. Supabase → Table Editor → 选中 `submissions` 或 `photos` → **Import data from CSV**；
3. 若 CSV 已含 `id` 列且与现有记录冲突，先清空表或改名导入后再合并；
4. 导入后刷新管理后台确认条数。

## 4. 恢复场景 B：表被删 / 项目重建（从零恢复）

Supabase SQL Editor 依次执行以下建表语句（与当前线上结构一致），再按场景 A 导入 CSV：

```sql
-- 报名表
create table if not exists public.submissions (
  id          bigint generated by default as identity primary key,
  name        text not null,
  class       text,
  contact     text not null,
  interest    text,
  intro       text,
  handled     boolean default false,
  created_at  timestamptz default now()
);

-- 作品表
create table if not exists public.photos (
  id             bigint generated by default as identity primary key,
  category       text not null,
  title          text not null,
  author         text,
  shot_date      date,
  file_url       text not null,
  status         text not null default 'pending',
  exif           jsonb,
  reject_reason  text,
  featured       boolean default false,
  created_at     timestamptz default now()
);

-- 服务端读写权限（service_role 全权）
grant all on public.photos, public.submissions to service_role;
```

> 表被删后 `file_url` 仍指向 COS 上的真实对象，只要桶还在，图片就还能正常显示——**所以图片丢不丢，只看桶**。

## 5. 图片资产的保护对策（建议二选一或都做）

| 方案 | 成本 | 说明 |
| --- | --- | --- |
| **COS 开启版本控制** | 按存储量计费（很小） | 误删/覆盖可回滚，性价比最高，推荐先开 |
| **每月手工快照** | 免费，费人力 | 每月备份时顺手在 COS 控制台把 `_backup/` 与当月新增作品下载到本地/移动硬盘，双份保管 |

> 已开「版本控制」后，即使水印覆盖、换图覆盖也能找回历史版本。

## 6. 演练清单（每学期一次，约 10 分钟）

- [ ] 后台点「立即备份」，确认返回当月 CSV 且签名链接可下载；
- [ ] 打开 `_backup/` 下的 CSV，确认条数与后台显示一致；
- [ ] 匿名访问 `https://ltyzglimmer-photos-1495891073.cos.ap-guangzhou.myqcloud.com/_backup/任意文件名.csv` → 应为 **AccessDenied**（防止备份被公开下载）；
- [ ] 确认 COS 版本控制状态（如已开启）；
- [ ] 确认环境变量清单与桶策略文档仍在安全的地方（不在仓库里）。

## 7. 出事时的第一反应（速查）

1. **数据没了** → 拿最近一份 CSV，按场景 A/B 恢复；
2. **图片没了** → 检查桶是否还在、是否欠费；有版本控制就走回滚，否则只能靠本地快照；
3. **后台进不去** → 环境变量 `ADMIN_PASSWORD` 在 Vercel 重新设置 → Redeploy；
4. **接口全挂** → 看 Vercel 函数日志 + `x-glimmer-rev` 确认线上版本，必要时回滚到上一个 Deployment。
