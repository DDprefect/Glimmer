# 微光网站 · 活动系统（v2.7.0）

> 面向干部的运维说明。活动 = 官网首页活动卡 + 活动详情页（介绍/报名/作品相册）+  
> 投稿页活动入口 + 后台全生命周期管理。

---

## 1. 一句话架构

```
后台「活动」标签（创建/发布/归档）
        ↓ 写 Supabase events 表（draft → published → archived）
官网首页「社团活动」区块 ← GET /api/events
活动页 event.html?id=N  ← 介绍 + 报名表单（POST /api/event-register）+ 作品相册
投稿页分类栏「参与活动」 ← 活动期间自动出现，照片带 event_id 仍走先审后发
```

**零改动复用**：报名字段与招新完全一致（姓名/班级/联系方式/留言），报名记录进  
同一张 `submissions` 表（打 `event_id` 标记），投稿进 `photos`（打 `event_id`）。

## 2. 干部操作手册

| 动作                        | 效果                                                     |
| ------------------------- | ------------------------------------------------------ |
| 新建活动 → 填标题/日期/介绍 → **保存** | 存为草稿，官网不可见；草稿可编辑、可删除                                   |
| 点**发布**                   | 官网首页出现活动卡、活动页可访问、报名开启、投稿页出现「参与活动」下拉                    |
| 点**归档（结束活动）**             | 首页卡片移入「往期」、报名关闭、投稿页活动入口消失；**活动页保留为「已结束」回顾**（介绍与作品相册仍在） |
| 查看报名 / 导出 CSV             | 每个活动的报名名单独立查看，含「已联系」标记，可单独导出                           |
| 重新发布                      | 归档的活动可再次上线（报名重新开启）                                     |

规则：一次可并行多个活动，互不干扰。**删除规则（v2.7.2）**：
- 草稿：直接删，无副作用；
- 已归档：可删。删除时**该活动的报名记录一并真删**（参与人信息随之消失——删前先「查看报名」导出 CSV 备份），挂靠的作品解除与活动的关联（`event_id` 置空），**作品本身保留在作品集**；确认弹窗会明确警告；
- 进行中：**不能删**（官网正在展示，误点代价太大），先归档再删——两步设计防手滑。

## 3. 数据模型

`events` 表（`_tools/EVENTS_SQL.sql` 建立，幂等可重跑）：

| 字段                      | 类型              | 说明                                          |
| ----------------------- | --------------- | ------------------------------------------- |
| id                      | bigint identity | 主键                                          |
| title                   | text not null   | 活动标题（≤60 字符，接口层校验）                          |
| content                 | text            | 活动介绍，纯文本多段，换行原样展示（≤5000）                    |
| activity_date           | text            | 活动日期，仅展示用（YYYY-MM-DD）                       |
| status                  | text            | draft / published / archived（接口层校验，无 DB 约束） |
| created_at / updated_at | timestamptz     |                                             |

挂接列：`submissions.event_id`（活动报名）、`photos.event_id`（活动投稿）。

**必须跑一次 SQL 才能用**：没跑之前后台活动标签会显示红色提示（含文件路径），  
公开接口返回空列表，上传页无活动入口——站点其余功能零影响。跑完刷新后台即生效。

## 4. 接口契约

| 端点                                                                     | 方法   | 鉴权 | 说明                                                |
| ---------------------------------------------------------------------- | ---- | -- | ------------------------------------------------- |
| `/api/events`                                                          | GET  | 公开 | `{ok,current[],past[]}`；表未建降级空列表                  |
| `/api/events?id=N`                                                     | GET  | 公开 | 详情 + `works[]`（该活动已审核作品）；draft 一律 404             |
| `/api/event-register`                                                  | POST | 公开 | `{eventId,name,class,contact,intro}`；同联系方式同活动幂等提示 |
| `/api/admin` action=`event_save`                                       | POST | 密码 | 创建/编辑                                             |
| `/api/admin` action=`event_publish` / `event_archive` / `event_delete` | POST | 密码 | 状态流转；仅 draft 可删                                   |
| `/api/admin` action=`event_regs` / `export_event`                      | POST | 密码 | 活动报名列表 / 导出 CSV                                   |

报名安全与 `/api/register` 同款：来源检查、单 IP 5 次/10 分钟（独立场景）、  
报名类全局熔断 20 条/10 分钟、蜜罐（前端 `ev-hp` 字段）、字段清洗。  
投稿挂靠校验：活动必须 `published`，归档/不存在一律 400。

## 5. 与既有体系的交互

- **作品集**：活动投稿审核通过后正常出现在作品集（不因为挂活动就隐藏）。
- **报名统计**：后台「报名列表」（KPI/筛选/导出）只含招新报名（`event_id is null`）；  
  活动报名进各活动的「查看报名」。
- **通知**：活动报名推送标题带活动名；活动投稿通知与普通投稿一致。
- **待审核卡片**：会显示「活动：〈名称〉」金色标记。
- **备份**：报名与照片都在主表 CSV 里，随月度备份落盘，无额外备份负担。

## 6. 已知边界

1. 活动介绍是纯文本（换行原样展示），不支持图片/富文本——学生场景够用，要封面图再说。
2. 活动页 `noindex`（动态 URL 不进 sitemap）；活动卡在首页，搜索引擎可经由首页发现。
3. 归档活动的前台入口只在首页「往期」小卡，不单独做归档列表页。
4. 报名防重复按「联系方式原文精确 + ilike 包含」两级匹配，改一个字符可以绕过——  
   对社团场景够用，恶意刷报名有限流兜底。
